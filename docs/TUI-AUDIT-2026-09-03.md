# curses-themes TUI Audit — 2026-09-03

## Verdict

The repository is a good home for reusable TUI primitives, but it is currently too theme/widget-focused to serve as the complete shared curses interaction layer.

## Existing strengths

- ThemeManager and Theme provide semantic/component color abstractions.
- Terminal-aware color initialization and fallback are already centralized.
- Reusable widgets exist: `Dropdown`, `Tabs`, and `Table`.
- The package is dependency-free at runtime and intended for Python curses applications.

## Gaps relevant to agent-setup

- No public mouse/input module exists.
- No reusable mouse capability/fallback API exists.
- No public `KEY_MOUSE`/`getmouse()` abstraction exists.
- No reusable scroll-aware list hit-testing primitive exists.
- Widget mouse behavior is incomplete/inconsistent with the widget docstrings: `Dropdown` is documented as mouse-friendly but its current selection loop only handles keyboard keys; `Tabs` is documented as mouse-supported but its handler only accepts keyboard input.
- Application code in `agent-setup` therefore currently owns low-level mouse behavior that is likely to be reused by future applications.

## Architectural decision

Extract generic terminal interaction primitives into `curses-themes` rather than duplicating them in each application. Keep domain-specific selection actions in the consuming application.

## Recommended API shape

Prefer small composable primitives over a framework-heavy event system. A first release can expose:

- `MouseSupport` or equivalent capability helpers
- `MouseEvent` value object
- `is_mouse_event(key)`
- primary-button activation predicates
- `list_index_at(...)`
- `resolve_list_mouse(...)`
- reusable list/select widget behavior

The exact names should be finalized against the existing package style before implementation.

## Agent-setup disposition

PR #89 should not permanently add low-level curses input infrastructure to `agent-setup`. Its application-specific integration and regression coverage are still valuable. The reusable implementation should move to `curses-themes`, after which `agent-setup` should consume the released API.

## Follow-up

Implement the extraction in a focused `curses-themes` PR, release it, update `agent-setup` to the new pinned version, and then simplify PR #89 so it contains only the necessary application integration and tests.
